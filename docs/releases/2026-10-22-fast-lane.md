# Fast lane (2026-10-22)

**Problem:** proposals were drafted minutes after a listing appeared, but a twice-daily review surfaced them 3–12 hours later, when listings had 80–200 bids or were already awarded.

**Change:** `scripts/studio-fast-lane.mjs` runs at the end of every 5-minute discovery tick. For each drafted lead with fit `strong`, score ≥ 60, age ≤ 8 h, no red flags and ≤ 30 bids, it re-checks the listing live on Freelancer's public API. If the listing is still open and uncrowded, it sends a ping with the finished cover letter, price and link: a JSON file in the ping outbox plus a macOS notification, one per lead, at most 6 a day.

In this release it never bids, deposits, messages clients or accepts work.

- Config, state and receipts: `data/studio/fast-lane.json` (`node scripts/studio-fast-lane.mjs` shows status)
- Off: `node scripts/studio-fast-lane.mjs mode off`, or create `data/studio/FAST-LANE-PAUSED`
- Dry run: `node scripts/studio-fast-lane.mjs --dry`
- Tests: `scripts/studio-fast-lane.test.mjs`

**Fixed during verification:** the first wiring deadlocked. The fast lane dynamically imported `studio-sources.mjs` during that module's own top-level await, so every discovery tick exited with code 13. Listings are now passed in. Drop reasons now report Freelancer's `sub_status` (for example `frozen_awarded`).
